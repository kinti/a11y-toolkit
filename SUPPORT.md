# Support — how to get help with a11y-toolkit

## 1. Docs first

- [README](README.md) — capabilities, install, the whole CLI.
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — the one-file map: every
  module, the decision log (D1-D22) and the trap catalogue (T1-T12).
- [docs/tools.md](docs/tools.md) — every MCP tool, generated from the
  server (never stale).
- In the CLI: `a11ytoolkit criterion <code>` explains any criterion;
  `a11ytoolkit route --goal "..."` picks the tools for your task.

## 2. Questions → GitHub Discussions

Open a thread in
[Discussions → Q&A](https://github.com/kinti/a11y-toolkit/discussions/categories/q-a)
with: what you ran, what you expected, what came out. The maintainer
answers; good threads become docs.

## 3. Bugs and feature requests → Issues

- [Bug report](https://github.com/kinti/a11y-toolkit/issues/new?template=bug_report.yml)
- [Feature request](https://github.com/kinti/a11y-toolkit/issues/new?template=feature_request.yml)
- Security-sensitive? Do NOT open an issue — see [SECURITY.md](SECURITY.md)
  for the private channel.

## 4. What support is NOT

Support never includes a conformance claim: the toolkit finds, a person
signs. If you need a signed accessibility report for a product, that is
the commercial service at [a11y.es](https://a11y.es).
