# The a11y evidence pack — schema `a11y-evidence-pack/3`

The machine→human handoff object for WCAG conformance work: what machines
found, what remains for a human, tamper-evident by construction. Any
qualified human (consultant, marketplace auditor, internal reviewer) can
review it; the toolkit never claims conformance itself.

Generated by `a11y_evidence` (MCP) or `a11ytoolkit evidence` (CLI). The
canonical implementation is [`a11yevidence.py`](../a11y_toolkit/a11yevidence.py) (MIT);
this document is the citable spec. A generated sample (fixture page, current
builder output): [`evidence-pack.sample.json`](evidence-pack.sample.json).

## Fields

| Field | Type | Meaning |
|---|---|---|
| `format` | string, always `a11y-evidence-pack/3` | Format and major version. The verifier accepts v2 and v3. |
| `generated` | ISO 8601 UTC | When the pack was built. |
| `tool` | string | Producing tool and repo. |
| `summary` | object | Counts per status over the whole matrix: `automated-fail`, `automated-review`, `not-flagged`, `manual-only`, `agent-verified`, `not-run`. |
| `criteria` | array | **The full matrix — exactly the 55 normative WCAG 2.2 A/AA criteria.** One entry per criterion: `{criterion: "1.4.3 Contrast (Minimum)", status, note?, value?, effort?}`. `value` carries the measured fact (e.g. `{measured: "3.91:1", example: "button"}`) when the finding contains one — the reviewer sees the number, not just the verdict. Statuses: `automated-fail` (a signal fired), `automated-review` (a low-severity/review signal fired), `not-flagged` (no signal fired on this sample — **explicitly NOT pass**), `not-run` (the tool HAS a signal for this criterion but the report type that carries it was not included), `manual-only` (no automated signal exists in the producing tool), `agent-verified` (an agent or human verified this criterion against this sample per the manual-checklist protocol — verification NEVER erases an `automated-fail`). Every row also carries `effort: {class, why}` — the human-effort class (below) and why review is needed. |
| `effort_pending` | object | Remaining review grouped by effort class: `{by_class: {MIN: {criteria}, …}, note}`. Verified and excluded rows are omitted. |
| `manual_pending` | array of strings | The criteria still needing human coverage (the `manual-only` subset NOT yet `agent-verified`). |
| `verification` | object? | Present when criterion codes were passed as verified: `{source: "agent"|"human", protocol}`. |
| `artifacts` | array | The input reports. Each: `{type: "report:static\|report:rendered\|report:reflow\|report:keyboard\|report:scroll" \| "snapshot:a11y", url?, score?, sha256, body}`. `sha256` = SHA-256 of the artifact's canonical JSON. `body` = the full report body, **embedded** — the pack is self-verifying: a verifier holding only the pack can recompute both `pack.sha256` and every `artifacts[].sha256` without needing the original reports. |
| `reviewer` | object | The signature block, empty by design: `{name, credential, review_date, statement, note}`. `statement` is what the human asserts; `note` states the signing rule (below). |
| `notes` | string? | Free text from the producer. |
| `notice` | string | The standing honesty statement: evidence, not conformance. |
| `sha256` | string | **Pack hash**: SHA-256 of the pack's canonical JSON **with the `sha256` and `generated` fields removed** (since 5.13.0 — re-emitting the same evidence yields the same seal; before that, only `sha256` was removed). Any post-seal edit of any **sealed** field breaks it; `generated` is deliberately outside the seal. |

For report artifacts, `report_status` is `complete`, `partial`, `failed` or
`invalid`. Coverage comes from usable page reports with a URL or file and a
findings list. A partial crawl contributes the pages that ran. Its errors are
retained in the artifact. Older packs can omit `report_status`. The verifier
recomputes it from the report body and checks it separately from the seal.
Truncated documents can be archived as `partial` and contribute no automated
coverage. Packs predating this check can have an intact seal and an incorrect
recorded measurement status. Rebuild those packs from complete measurements.
Findings with `disprover_status: "not-rechecked"` remain in the embedded
report and contribute `automated-review` to the criterion matrix.
Rejected historical findings remain in the embedded report. The matrix
derives both its status and any measured values from active findings.

**Pack/2 rename (2026-09-23)**: every wire key is now English — `criterios`→`criteria`, `estado`→`status`, `esfuerzo`→`effort`, `artefactos`→`artifacts`, `evaluador`→`reviewer`, `informes`→`reports` (tool argument), `verificados`→`verified` (tool argument), `formato`→`format`, and the rest per the pack itself. Pack/1 packs remain valid historical documents; builders emit pack/3.


**Pack/1 compatibility note**: `agent-verified` and `verificacion` were added
as an additive extension within pack/1 (2026-09-15) — new optional status
value and field, no renames or removals, per the versioning promise below.

**Self-verifying (pack/1.1 change, 2026-09-19)**: artifact bodies are now
embedded in the pack. A verifier holding only the pack recomputes every hash
in the chain without external files. Previous packs (manifest-only) are
still valid pack/1 — they just need the reports alongside.

**Not-run state (sharpened 2026-11-22)**: a criterion is `not-flagged` only
when the sample includes an ACCEPTED report (one without `error`) of a mode
that can carry its signal — `MODES_BY_CRITERION` in `a11ycrit.py` is the
single source, re-derived from the emission points by the invariant tests.
Zero reports, error-only reports, or reports of other modes (a rendered audit
does not clear 2.1.2 — that is `a11y_keyboard`'s test) leave the criterion
`not-run`, and the note names the missing tool. This distinguishes "the
machine looked and found nothing" from "the machine was not asked to look."

## Content privacy (normative)

Findings describe **structure and measurements, never page content**. Alt
text, link text, headings, labels, error messages, form field values, and
any user-supplied text are the things that are **never quoted** in any
finding, example, or remediation string. The hallazgo field describes the
structural issue; ejemplos carry CSS paths, rgb() color pairs, pixel sizes,
and WCAG codes. If any finding text appears to quote page content, that is
a bug — report it.

## Effort classes

The matrix carries a review class and rationale for each applicable criterion.
The [class table](effort-class-table.md) defines what remains to review. Pack/3
counts criteria by class. Archived pack/2 objects retain their original seal
and can be verified with the same script.

## The hash rule (normative)

Canonical form is `json.dumps(obj, ensure_ascii=False, sort_keys=True,
separators=(',', ':'))` over UTF-8. `pack.sha256` is computed over the pack
minus `sha256` and `generated` (since 5.13.0; packs emitted before 5.13.0
sealed the clock in — minus `sha256` only); each `artifacts[].sha256` over
that artifact as embedded. Verifiers MUST recompute both before trusting a
signature.

## The composition rule (how a third party signs)

An external attestation must **reference, never restate**:

```json
{
  "evidence": {
    "format": "a11y-evidence-pack/3",
    "sha256": "<pack.sha256>",
    "generado": "<pack.generado>",
    "artifacts_verified": ["<sha256>", "<sha256>"]
  },
  "criterios_firmados": ["the manual-only list, or a subset actually reviewed"],
  "nombre": "…", "credencial": "…", "fecha": "…"
}
```

A reader follows the attestation to the pack by hash, recomputes the hash
chain, and never takes either document on trust. The two artifacts compose
instead of overlapping — the attestation adds the human judgment layer on
top of the machine evidence, and nothing is duplicated across the seam.

## Verify a pack (independent, no engine needed)

`scripts/verify_pack.py` is a STANDALONE verifier: copy that single file
anywhere with Python 3.9+ and check any pack — it recomputes the whole hash
chain from the pack alone (report bodies are embedded):

```
$ python3 scripts/verify_pack.py docs/evidence-pack.sample.json
OK    criteria matrix — 55 entries, known statuses
OK    summary counts match the criteria matrix
OK    artifact hashes — 1 recomputed from embedded bodies
OK    pack seal — recomputed over the pack minus sha256/generated
VERIFIED — the sealed hash chain holds
```

`--json` emits machine-readable output (`{verified, checks}`). Exit codes:
0 verified · 1 any failure, naming the field that broke the chain.

Two honest notes, pinned by `tests/test_verify_pack.py`:

1. **Seal rules.** Since v5.13.0 the seal excludes the clock (`generated`) —
   re-emitting the same evidence later yields the same seal; `generated`
   itself is therefore NOT tamper-evidenced. Packs emitted before v5.13.0
   sealed the clock in; the verifier accepts both and LABELS which rule
   matched ("legacy"). Any post-seal edit of any sealed field breaks both.
2. **Recorded artifacts.** Only `report:*` artifacts embed their body, so only
   their hashes are recomputable from the pack itself. `snapshot:a11y` /
   `sr_transcript` artifacts carry a recorded sha256 without a body — the
   verifier reports them as "recorded", not verified. Tampering with anything
   embedded still breaks the pack seal regardless.
